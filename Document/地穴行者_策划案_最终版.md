# 《地穴行者》毕设策划案（整合最终版）

> 2D 正俯视角 · 多武器动作肉鸽
> 定位：涵盖近战挥砍、远程投射、法术释放三大战斗品类，核心乐趣在于「元素词条组合 + 随机 Build 构筑」。
> 目标：本科毕设，单人开发 8 周落地，成品完整可玩，预留架构与性能优化空间。

## 0. 文档一致性说明（本版已修正的关键矛盾）

本版在总纲基础上，修正了以下逻辑冲突，写作时务必以此为准，避免写代码踩雷：

| 原问题 | 本版处理 |
| :--- | :--- |
| 元素印记上限与顶替逻辑矛盾 | 上限固定 **2 枚**；第 3 种元素仅当能与剩余印记组成有效反应时才替换旧印记，否则拒绝 |
| 元素反应伤害与主伤害公式双算 | 反应伤害为 **独立结算事件**，不进入主公式；主公式只承载武器 `elementDamage` 平A附伤 |
| 章节固定顺序 vs 随机游走冲突 | 采用「槽位数组 + 几何布局」**两级结构**：类型永远跟槽位走，几何只负责位置与门 |
| 词条表标16只列12 | 补全为 **16 种**词条池 |
| 防御公式描述含糊 | 改为标准式：`减伤系数 = 敌防 / (敌防 + 玩家攻击×穿透)`，敌防为真实属性按章节给区间 |
| 经验曲线导致满级不可达 | 下调为 `所需经验 = 当前等级×10 + 8`，并给出目标锚点表 |
| 俯视角渲染未覆盖 | 新增**渲染与遮挡层**细化，统一"格=1 Tile=1 世界单位" |

## 一、游戏基础定位

1. **游戏名称**：《地穴行者》
2. **游戏类型**：2D 正俯视角 动作肉鸽（Action Roguelike）
3. **核心特色**：多武器切换战斗 + 元素反应 Build + 随机房间生成 + 局外永久成长
4. **单局时长**：10~20 分钟
5. **目标平台**：PC / WebGL / 微信小游戏（逻辑层与平台无关）
6. **美术风格**：暗黑像素风，AI 生成素材统一风格
7. **视角定性（关键）**：正俯视角（90° 垂直俯视），单位统一为 **1 格 = 1 Tile = 1 世界单位**，所有半径/射程/击退均以此度量。

### 版本范围（毕设 8 周取舍）
- **第一档（必做，完整可玩）**：局内全流程 + 最简升级点 + 结算界面。
- **第二档（加分，建议做）**：双武器携带与切换、遗物系统首版 5 件、普通+困难两档难度。
- **第三档（预留接口，不落全代码）**：角色解锁池、完整天赋树、图鉴全量收录 ← 论文写成「扩展方向」。

## 二、核心玩法循环

### 局内循环
进入关卡 → 探索随机房间 → 击杀敌人获取经验/金币/掉落 → 升级随机三选一 Buff → 收集武器/词条/遗物 → 挑战精英与章节 Boss → 通关/死亡结算 → 获得局外永久货币。

### 局外循环
消耗永久货币 → 解锁武器/角色/基础天赋 → 下一局构筑更多流派 → 挑战更高难度。（毕设段作为预留接口）

### 3.2 元素反应机制（Build 核心）

**4 种元素**：火（灼烧）/ 冰（减速→冻结）/ 雷（连锁闪电）/ 毒（持续掉血+降防）。

**元素附着规则（修正后，务必按此实现）**：
- 每次攻击附带元素 → 给敌人挂**元素印记**，持续 5 秒。
- 每元素独立计时；**同一敌人最多同时存在 2 种印记**。
- 第 3 种元素贴上时：仅当能与剩余一枚印记组成**有效反应**时才顶替旧印记，否则拒绝。
- 内置冷却：同一敌人每 0.5s 只能触发一次元素反应。
- 反应触发后**清除参与反应的两枚印记**。

**四种反应判定与公式（独立结算，不进入主伤害公式）**：
| 反应 | 条件 | 效果公式 | 额外效果 |
| :--- | :--- | :--- | :--- |
| 蒸汽爆炸 | 火+冰 | 半径3格，伤害 = 攻击×1.8 | 致盲 2s（攻击 50% Miss） |
| 过载爆发 | 火+雷 | 半径4格，伤害 = 攻击×2.2 | 击退 3 格，打断施法 |
| 感电连锁 | 冰+雷 | 初始 = 攻击×1.2，连锁 +1 次 ×1.15 | 最多链 5 敌，自动索敌 |
| 剧毒爆燃 | 火+毒 | 伤害 = 已损生命×25%（Boss 衰减至 10%） | 移除目标全部毒层 |

**判定伪逻辑（Update 检测）**：
```
OnHit(enemy, elementType):
    if enemy.CanApply(elementType): enemy.AddMark(elementType, 5.0f)
    if enemy.HasMark(Fire) and enemy.HasMark(Ice) and not enemy.reactionCooldown:
        TriggerVaporExplosion(enemy)
        enemy.RemoveMark(Fire); enemy.RemoveMark(Ice)
```

**实现归属**：元素印记做成 `EnemyElementMarks` 组件挂敌人身上，与 Combat 正交解耦，反应触发走事件队列。新增元素/反应无需改武器系统。

### 3.3 伤害计算（统一公式）

```
最终伤害 = (基础攻击力 × 武器倍率 × (1 + 攻击力加成%) + 固定附加伤害)
         × 暴击倍率(若触发，150%起，上限300%)
         × 防御减伤系数(敌人)
         × 难度修正系数
         × 随机浮动 0.95~1.05
```
- 武器倍率：长剑 1.0 / 巨斧 1.8 / 匕首 0.6(高攻速) / 长弓 1.3(蓄满 2.0) / 连发铳 0.4×5 / 法杖 1.2。
- 防御减伤：`减伤系数 = 敌防 / (敌防 + 玩家攻击×穿透)`，敌防为真实属性，第一章 10~20、第二章 20~35、第三章 35~50，减伤上限 50%。
- **全部加成走统一 Modifier 聚合管道**，避免数值漏算/多算：

```
float CalcFinalDamage(WeaponData weapon, EnemyBase target) {
    var m = ModifierPipeline.Build();               // 一次性聚合 Buff/词条/遗物/元素
    float atk = weapon.baseAttack * weapon.multiplier * (1 + m.attackPct) + m.flatAtk;
    float dmg = atk * GetDefFactor(target.def, m.pierce);
    dmg *= m.crit && Roll() ? m.critMult : 1f;
    return dmg * Random.Range(0.95f, 1.05f);
}
```

## 五、关卡与敌人

### 5.1 关卡结构（两级：槽位 + 几何）

**第一级 · 章节槽位数组**（类型固定，跟随进度）：
`[起始] → [普通×4] → [精英] → [普通×4] → [商店/休息] → [Boss]`（12 间）

**第二级 · 几何布局**（只负责位置与门，不改变类型）：
```
1. 初始化 6×6 网格，中心放起始房 (0,0)
2. 随机游走（步长1，上下左右）铺出 12 个房间坐标
3. BFS 校验连通性：孤立房间强制与最近房间打通门
4. 房间类型严格按槽位数组分配，几何不干预
5. 为每个房间随机选 3 套内置障碍模板之一，生成障碍（避开出生点与门）
6. 每房最多 4 门，与相邻房间对应
```
> 类型约束与随机性彻底解耦，连通性有 BFS 保证，毕设级轻量，无需实时 dungeon 算法。

### 5.2 敌人体系

**普通（8 种）**：冲锋怪 / 近身挥砍怪 / 远程投射怪 / 自爆怪(带元素) / 护盾怪(需对应元素破盾) …… 等 8 种。
**精英（4 种）**：自带随机强化词条（加速/增伤/回血/护盾），血量伤害远高于普通怪。
**Boss（3 只，对应 3 章，每只 2 阶段）**：第一章洞穴蠕虫（钻地突袭/范围吐毒/召唤小怪）。

**属性随章节递增公式**：
```
敌人等级 = 基础等级 + (章节-1)×3 + (房间深度索引/4)
生命 = 基础生命 × (1 + 0.25×等级)
攻击 = 基础攻击 × (1 + 0.15×等级)
经验 = 基础经验 × (1 + 0.1×等级)
```
章节 Boss 固定 Lv.5 / Lv.10 / Lv.15（基础属性再 ×1.5）。

### 5.3 敌人 FSM（可配置化扩展）

| 状态 | 行为 | 进入条件 | 退出条件 |
| :--- | :--- | :--- | :--- |
| Idle | 原地待机 | 生成/丢失目标 | 玩家进视野(半径6格) |
| Patrol | 原点半径3格内随机移动 | Idle 持续 2s | 检测到玩家 |
| Chase | 向玩家移动(1.2×基础速) | 玩家进视野 | 出视野8格 或 进攻击范围 |
| Attack | 攻击动画+伤害判定 | 玩家进攻击半径(近战1.5/远程6) | 动画结束 |
| Hit | 受击后仰，硬直 0.2s | 受到伤害 | 硬直结束 |
| Death | 死亡动画+掉落物 | 生命≤0 | 动画结束销毁 |

**Boss 专属**：Summon（召唤小怪）、Charge（蓄力冲刺，红圈预警 1.5s）。
**转换优先级**：`Death > Hit > Attack > Chase > Patrol > Idle`。

**实现骨架（推荐，替代 switch）**：
```csharp
public abstract class EnemyState<T> where T : EnemyBase {
    protected T self; protected StateMachine<T> fsm;
    public abstract void OnEnter();
    public abstract void OnUpdate();
    public abstract void OnExit();
}
```
状态与转换表走 JSON 配置化，呼应"配置化 AI"答辩点，比行为树轻量。

| 对象 | 初始 | 上限 | 超容量策略 |
| :--- | :--- | :--- | :--- |

| 精英/Boss | 2 | 5 | 临时扩池 |
| 玩家弹道 | 30 | 60 | 临时扩池 |
| 敌人投射物 | 20 | 40 | 临时扩池 |

public interface IPoolable {

## 九、俯视角渲染实现层（本版新增补丁）

正俯视角下，渲染/朝向/遮挡与横版不同，单独成层：

1. **朝向**：敌人不用左右翻转（那是横版做法），用 **Z 轴旋转 + 移动方向偏置**，做 4 向（上/下/左/右）即可，美术量省 3/4。`LookAt` 不适用于正俯视角，需换算成 Z 轴旋转角。
2. **单位统一**：1 格 = 1 Tile = 1 世界单位，攻击半径/视野/击退/AOE 全部用同一 `Vector2` 距离度量。
3. **碰撞**：长弓/连发铳弹道用圆形 Collider2D，命中判断以 2D 距离为准；AOE 落成"以目标为中心圆形范围检测"，与 Tilemap 坐标对齐。
4. **遮挡透视（正俯视角最大坑，答辩亮点）**：
   - 玩家被障碍挡时，把遮挡物设为**半透明(约 40%)**，或用"受挡时抬升渲染层级"。
   - 敌人血条 / Boss 红圈预警 / 掉落物：红圈直接画在**地面 Projector 层**（印在地上），天然免遮挡。
   - 用 `Sorting Order` + 图层管理统一层级。
5. **命中反馈方向**：受击后仰、击退方向**跟随攻击来袭反方向**（相对量），不用死方向，影响 Hit 状态与击退逻辑。
