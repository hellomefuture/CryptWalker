# 地穴行者 · 玩家美术需求清单

> **目的**：把玩家从「帧内自带长剑」改造成「身体无武器 + 武器独立贴图」，以支持元气骑士式的武器旋转。
> **范围**：玩家角色（Swordsman）身体图、新增的武器贴图与弹道贴图。
> **状态**：清单已按现有素材实测核对，规格部分可直接交给画师。

---

## 0. 一条总原则（最重要）

**新图必须与现有图集「完全同构」** —— 每帧 64×64、4 行、行序不变、列数与现在一一对应。

做到这一点，现有 **32 个动画片段（`.anim`）和所有代码都不用动**，纯粹是换图。
一旦布局变了，32 个片段必须重建，工作量大一个数量级。

### 替换时的操作要求

| 要求 | 说明 |
|---|---|
| **用新图直接覆盖同名文件** | 保留原 `.meta` **不要删** |
| 为什么 | `.anim` 里引用的是**切片后的 sprite ID**，而这些 ID 存在 `.meta` 里。`.meta` 一旦被重建，32 个动画片段的引用会全部失效（表现：角色不动 / 播不出动画） |
| 覆盖后 | 回到 Unity 让它重新导入，Console 无报错即说明切片与片段引用都还完好 |

## 1. 技术规格（硬要求，不能变）

| 项目 | 规格 |
|---|---|
| **每帧尺寸** | **64 × 64 px** |
| **图集高度** | **256 px**（= 4 行 × 64） |
| **行顺序（从上到下）** | **South → Left → Right → North** |
| **列数** | = 该动作每方向的帧数（见 §3） |
| **Pixels Per Unit** | **16** ← 所有新图（身体 / 武器 / 弹道）都按这个比例，否则大小不对 |
| **采样率** | **12 fps** |
| **Filter Mode** | **Point (no filter)** |
| **Pivot** | **Center（0.5, 0.5）** |
| **Sprite Mode** | **Multiple**（需要切片） |
| **压缩** | 不压缩（Standalone / Default 平台） |
| **Alpha Is Transparency** | 开 |
| **现有存放位置** | `Assets/Art/Character/Player/Swordsman/lvl1/WithShadow/` |
| **现有命名** | `Swordsman_lvl1_{动作}_with_shadow.png` |

### 行序是怎么确认的（供复核）

用各方向动画首帧引用的 sprite ID 反查切片矩形（`y` 以图集底边为 0）：

| 方向 | 切片 `y` | 对应行 |
|---|---|---|
| South | 192 | 第 1 行（最上） |
| Left | 128 | 第 2 行 |
| Right | 64 | 第 3 行 |
| North | 0 | 第 4 行（最下） |

与代码里的方向协议一致：`PlayerController` 中 `1=South 2=Left 3=Right 4=North`。

## 2. 现状核实（避免重复排查）

| 项目 | 现状 |
|---|---|
| 动画片段总数 | **32 个**，命名 `Swordsman_{动作}{方向}` |
| 动作名 | `Idle / Walk / Run / Attack / WalkAttack / RunAttack / Hurt / Death` |
| 方向名 | `South / Left / Right / North` |
| 片段命名规则 | `PlayerController.PlayAction` 拼 `{characterName}_{动作}{方向}`，`characterName` 默认 `Swordsman` |
| 玩家预制体结构 | **只有 3 个节点**：`player`（1 个 SpriteRenderer + 1 个 Animator）、`cm`、`PlayerCamera` |
| 武器 / 挂点节点 | **不存在**（`firePoint` 字段为空，没有 `WeaponPivot` / `Muzzle` 节点） |
| 阴影 | **烘在贴图帧里**（`_with_shadow`），预制体上没有独立影子节点 |
| 武器配置资产 | `WeaponConfig` 的 SO **一个都没有**（代码有，数据缺） |

**结论**：剑和阴影都烘在每一帧里，所以现在是「待机时也永远举着剑」，且没有放武器贴图的位置。

## 4. 需要的内容（按优先级）

### 4.1 第一批 —— 必须：无剑身体（3 张 / 104 帧）

这是「最短路径」，有这 3 张就能做元气骑士式武器旋转。

| 动作 | 每方向帧数 | 图集尺寸 | 总帧数 |
|---|---|---|---|
| **Idle** | 12 | 768 × 256 | 48 |
| **Walk** | 6 | 384 × 256 | 24 |
| **Run** | 8 | 512 × 256 | 32 |
| | | **合计** | **104 帧 / 3 张图** |

**要求**：完全去掉手中武器；姿势与现有素材保持同一套（步态、体型、朝向），只有武器消失。

---

### 4.2 第二批 —— 必须：主场武器贴图（1 张先跑通）

| 项目 | 要求 |
|---|---|
| 存放 | `Assets/Art/Weapon/Player/` |
| 尺寸 | 按 **PPU = 16** 画。长剑建议 **16×48** 或 **32×64** |
| **Pivot** | **定在「握把」位置**，不要用图形中心 |
| 数量 | 单图连续旋转 = **1 张 / 武器**；8 方向离散 = 8 张 / 武器 |
| 建议 | **先做单图 1 张**（最省）。代码里会留开关，以后想改 8 方向只换图、不重写代码 |
| 先要哪把 | **长剑 1 张**即可跑通整条链路；长弓、法杖随后 |

> ⚠️ 不要和 `Assets/Art/ui_Texture/weapon_sword.png` 混了 —— **那是 UI 图标**，不是手持武器贴图。

---

### 4.3 第三批 —— 需要但不急：受击 / 死亡无剑版（2 张 / 48 帧）

| 动作 | 每方向帧数 | 图集尺寸 | 总帧数 |
|---|---|---|---|
| **Hurt** | 5 | 320 × 256 | 20 |
| **Death** | 7 | 448 × 256 | 28 |

可以先复用旧图，但会出现「身体无剑、受伤帧有剑」的穿帮。优先级低于 4.1。

---

### 4.4 第四批 —— 弹道与其余武器

| 内容 | 要求 |
|---|---|
| 存放 | `Assets/Art/Weapon/Projectile/` |
| 箭矢（长弓用） | **16×16** 或 **32×32**，按 PPU = 16 |
| 元素弹（法杖用） | **16×16** 或 **32×32**，按 PPU = 16 |
| 长弓 / 法杖手持贴图 | 同 §4.2 规格，各 1 张 |

> 弹道是**独立飞行 + 需要对象池**的对象，所以只有它需要做成**预制体**。
> 手持武器**不需要**预制体 —— 它是玩家身上的一个支点节点 + 一张贴图。

## 5. **不需要**重画：攻击类动作（3 张 / 88 帧）

| 动作 | 每方向帧数 | 图集尺寸 |
|---|---|---|
| Attack | 8 | 512 × 256 |
| WalkAttack | 6 | 384 × 256 |
| RunAttack | 8 | 512 × 256 |

武器独立显示后，**攻击表现由武器自身挥动**，身体不需要攻击帧。**省下 88 帧工作量** —— 这是本方案最大的收益。

> ⚠️ **但不能直接删文件**：`PlayerFSM` 的攻击状态会调 `PlayAction("Attack")`，clip 不存在会导致静默播不出来（角色卡在上一帧）。
> 正确做法是**保留旧图过渡**，或**同步修改 FSM 让攻击状态播 Idle**（这一步是代码改动，由程序侧处理）。

## 7. 强烈建议：先翻素材包原始文件（在做 4.1 / 4.3 之前）

现有目录结构透露了两个信号：

```
Assets/Art/Character/Player/Swordsman/lvl1/WithShadow/
```

| 信号 | 推测 |
|---|---|
| **`lvl1`** | 素材包作者很可能还有 `lvl2`、`lvl3`（通常是不同武器 / 不同等级的外观） |
| **`WithShadow`** | 说明素材包里**应该有「无阴影版」**；这类包**经常同时提供「无武器版」或「武器分层版」** |
| 目录下有两张**独立的**影子图 | `shadow_single.png`、`shadow_death.png`（当前预制体未引用）→ 说明这个包原本很可能是**分层**的 |

**如果素材包里存在「无武器」或「武器分层」版本，本清单的 §4.1 与 §4.3 可能一块都不用画。**
这一步零成本，务必先做。

## 附：实现方案对应的节点结构（供参考，程序侧实现）

```
Player (身体 SpriteRenderer + Animator)
├── WeaponPivot          ← 武器支点（绕它旋转）
│    └── WeaponVisual    ← SpriteRenderer = 武器贴图（Pivot 在握把）
│         └── Muzzle     ← 弹道发出点（对应 PlayerController.firePoint）
```

- 数据侧：`WeaponConfig` 增加视觉字段（武器贴图、支点偏移、握把前伸量、是否角度吸附）
- **换武器 = 换一张贴图**，不需要实例化任何预制体
